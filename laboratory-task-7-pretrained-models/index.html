Laboratory Activity 7: Image Classification Using Pre-trained Models¶

Instruction: Find or build an image classification dataset, curate it, write a custom PyTorch Dataset class and DataLoader objects for it, then run inference with up to five pre-trained models from torchvision.models. Compare the models using accuracy, precision, recall and F1-score, present the comparison with tables and visualizations, and close with a short analysis of why the models performed differently.

The dataset for this lab is Cats vs. Dogs. It is a good fit for models pre-trained on ImageNet because ImageNet already contains both animals: classes 281–285 are domestic cats (tabby, tiger cat, Persian, Siamese, Egyptian cat) and classes 151–268 are 118 individual dog breeds. That means no training or fine-tuning is needed — each model predicts one of its 1,000 ImageNet classes, and that prediction is mapped back to cat, dog, or other (anything that is neither, e.g. "lynx", "teddy bear", "wolf"). An other prediction always counts as a mistake, so the task is a little harder than a plain two-way choice.

The five models compared are ResNet-18, ResNet-50, MobileNetV2, EfficientNet-B0 and ViT-B/16 (Vision Transformer). They were picked to cover different design ideas: a small and a large residual CNN, two lightweight mobile-oriented CNNs, and a transformer that has no convolutions after its first patch-embedding layer.

3. Curating and Organizing the Dataset¶

Raw scraped images are messy, so before anything touches a model each file goes through four checks:

  1. It opens — PIL.Image.verify() catches truncated or corrupted JPEGs.

  2. It is big enough — anything under 64 px on its shorter side would be upscaled almost 4× to reach 224 px, so it is dropped.

  3. It is not a duplicate — the MD5 hash of the file bytes is used to remove exact copies.

  4. It is converted to RGB later in the Dataset, so grayscale or CMYK files do not break the 3-channel models.

From the clean images, 500 cats and 500 dogs are sampled with a fixed seed so the classes are perfectly balanced and the run is reproducible. They are copied into the standard one-folder-per-class layout, data/lab7_cats_dogs/{cat,dog}/, and a labels.csv file records each image's path and label.

4. Custom PyTorch Dataset Class¶

CatDogDataset reads labels.csv once, and then loads each image lazily inside __getitem__, so only one batch of images is ever in memory. Three things are worth pointing out:

  • transform is a constructor argument instead of being hard-coded, because the five models do not all want the same preprocessing (see Section 6). The same dataset object can be wrapped with a different transform for each model.

  • .convert('RGB') guarantees three channels no matter how the JPEG was saved.

  • The index is returned along with the image and label, so a wrong prediction can be traced back to its file for the error gallery at the end.

class CatDogDataset(Dataset):
    """Cats vs. dogs images listed in a CSV file (columns: filepath, label, class_name)."""

    def __init__(self, csv_file, root_dir, transform=None):
        self.df = pd.read_csv(csv_file)
        self.root_dir = root_dir
        self.transform = transform
        self.classes = CLASSES

    def __len__(self):
        return len(self.df)

    def __getitem__(self, idx):
        row = self.df.iloc[idx]
        image = Image.open(os.path.join(self.root_dir, row['filepath'])).convert('RGB')
        if self.transform is not None:
            image = self.transform(image)
        return image, int(row['label']), idx

5. Loading the Pre-trained Models¶

Each model is built from torchvision.models with its ImageNet-1k weights. MODEL_SPECS keeps everything about a model in one place: the torchvision builder, the official weights enum, and a backup weights file.

A note on the weights. torchvision downloads its weights from download.pytorch.org, and that host is blocked in the environment this notebook was run in (the same kind of problem as the MNIST download in Lab 6). So load_pretrained() first tries the normal torchvision call, and only if that fails it falls back to ImageNet-1k weights for the exact same architecture hosted on GitHub by the timm library. The architecture is still the torchvision one; only the numbers inside it come from a different training run. Those state dicts use different parameter names (e.g. conv_stem instead of features.0.0), so they are renamed before loading. load_state_dict is strict by default, so a wrong mapping would raise an error instead of silently loading garbage. The printed source column shows which weights each model actually used. On Colab or a normal PC the first branch succeeds and the official torchvision weights are used, so the numbers may shift slightly from the ones shown here.

def rename_by_order(src_sd, model):
    """Same architecture, different names: pair the tensors up in order and check every shape."""
    target = model.state_dict()
    assert len(src_sd) == len(target), 'parameter counts differ'
    new_sd = {}
    for (t_name, t_val), s_val in zip(target.items(), src_sd.values()):
        assert t_val.shape == s_val.shape, f'shape mismatch at {t_name}'
        new_sd[t_name] = s_val
    return new_sd


def rename_vit(src_sd, model):
    """timm stores ViT tensors alphabetically, so the ViT mapping is done by name instead."""
    new_sd = {'class_token': src_sd['cls_token'],
              'conv_proj.weight': src_sd['patch_embed.proj.weight'],
              'conv_proj.bias': src_sd['patch_embed.proj.bias'],
              'encoder.pos_embedding': src_sd['pos_embed'],
              'encoder.ln.weight': src_sd['norm.weight'], 'encoder.ln.bias': src_sd['norm.bias'],
              'heads.head.weight': src_sd['head.weight'], 'heads.head.bias': src_sd['head.bias']}
    names = {'norm1': 'ln_1', 'attn.proj': 'self_attention.out_proj', 'norm2': 'ln_2',
             'mlp.fc1': 'mlp.0', 'mlp.fc2': 'mlp.3'}
    for i in range(12):
        tv = f'encoder.layers.encoder_layer_{i}.'
        for p in ('weight', 'bias'):
            new_sd[tv + f'self_attention.in_proj_{p}'] = src_sd[f'blocks.{i}.attn.qkv.{p}']
            for timm_name, tv_name in names.items():
                new_sd[tv + f'{tv_name}.{p}'] = src_sd[f'blocks.{i}.{timm_name}.{p}']
    return new_sd


def mirror_transform(crop_pct, mean, std, size=224):
    return T.Compose([T.Resize(int(size / crop_pct), interpolation=T.InterpolationMode.BICUBIC),
                      T.CenterCrop(size), T.ToTensor(), T.Normalize(mean, std)])


def load_pretrained(name, weight_dir=os.path.join('data', 'weights')):
    spec = MODEL_SPECS[name]
    try:
        model = spec['builder'](weights=spec['weights'])
        transform = spec['weights'].transforms()
        source = f"torchvision {spec['weights']}"
    except Exception:
        os.makedirs(weight_dir, exist_ok=True)
        path = os.path.join(weight_dir, spec['mirror'].split('/')[-1])
        if not os.path.exists(path):
            urllib.request.urlretrieve(spec['mirror'], path)
        model = spec['builder'](weights=None)
        src_sd = torch.load(path, map_location='cpu')
        rename = rename_vit if name == 'ViT-B/16' else rename_by_order
        model.load_state_dict(rename(src_sd, model))
        transform = mirror_transform(**spec['mirror_pre'])
        source = 'timm ImageNet-1k (GitHub mirror)'
    return model.eval().to(device), transform, source

6. Preprocessing and DataLoader Objects¶

A pre-trained model only works well if test images are prepared the same way as its training images. All five expect a 224×224 RGB tensor, but they differ in how they get there: the resize size before cropping (set by the crop percentage), the interpolation method, and the normalization statistics. The ViT checkpoint, for example, was trained with pixels scaled to [-1, 1] (mean 0.5, std 0.5) rather than the usual ImageNet mean/std. Feeding it the wrong normalization quietly costs accuracy. That is why each model gets its own dataset + DataLoader pair built from its own transform.

shuffle=False keeps the image order identical across the five loaders, so predictions can be compared image by image. Batch size 32 is a comfortable size for CPU inference.

7. Model Inference¶

Every model outputs 1,000 ImageNet logits per image. imagenet_to_catdog() takes the top-1 class and maps it: indices 281–285 → cat (0), 151–268 → dog (1), anything else → other (2). torch.no_grad() switches off gradient tracking because nothing is being trained, which saves memory and time. The wall-clock time per image is also recorded (on this machine's CPU), since speed is part of what makes a model suitable or not.

CAT_IDX = range(281, 286)
DOG_IDX = range(151, 269)
IMAGENET_NAMES = models.ResNet18_Weights.IMAGENET1K_V1.meta['categories']
print('Cat classes :', [IMAGENET_NAMES[i] for i in CAT_IDX])
print('Dog classes :', len(DOG_IDX), 'breeds, e.g.', [IMAGENET_NAMES[i] for i in (151, 207, 235, 268)])


def imagenet_to_catdog(top1):
    out = torch.full_like(top1, 2)
    out[(top1 >= 281) & (top1 <= 285)] = 0
    out[(top1 >= 151) & (top1 <= 268)] = 1
    return out


@torch.no_grad()
def run_inference(model, loader):
    y_true, y_pred, top1_all, conf_all = [], [], [], []
    start = time.time()
    for xb, yb, _ in loader:
        probs = model(xb.to(device)).softmax(dim=1).cpu()
        conf, top1 = probs.max(dim=1)
        y_true.append(yb)
        y_pred.append(imagenet_to_catdog(top1))
        top1_all.append(top1)
        conf_all.append(conf)
    elapsed = time.time() - start
    return (torch.cat(y_true).numpy(), torch.cat(y_pred).numpy(),
            torch.cat(top1_all).numpy(), torch.cat(conf_all).numpy(), elapsed)


results = {}
for name, (model, _) in loaded.items():

    print(f"{name:16} done in {elapsed:6.1f} s  ({elapsed / len(y_true) * 1000:5.1f} ms / image)")

8. Evaluation Metrics¶

The four metrics answer slightly different questions:

  • Accuracy — out of all 1,000 images, how many got the right animal?

  • Precision — when the model says "cat", how often is it really a cat? (and the same for dog)

  • Recall — out of all real cats, how many did the model find? (and the same for dog)

  • F1-score — the harmonic mean of precision and recall, high only if both are high.

Precision, recall and F1 are macro-averaged over the two real classes (labels=[0, 1]), so cats and dogs count equally. An other prediction cannot raise precision for any class but it lowers recall, which is the right penalty for a model that looked at a cat and said "lynx". The "Other %" column shows how often that happened.

rows = []
for name, r in results.items():
    model = loaded[name][0]
    prec, rec, f1, _ = precision_recall_fscore_support(r['y_true'], r['y_pred'], labels=[0, 1],
                                                       average='macro', zero_division=0)
    rows.append({'Model': name,

11. Analysis¶

Overall ranking. By F1-score the order is ViT-B/16 (0.963) > ResNet-50 (0.937) > EfficientNet-B0 (0.927) > ResNet-18 (0.913) ≈ MobileNetV2 (0.911). Accuracy gives the same order except that MobileNetV2 (0.888) edges out ResNet-18 (0.883). The gap between best and worst is about 5 accuracy points, which is 54 more correctly classified images out of 1,000. No model was fine-tuned, so every difference here comes from what the models already learned on ImageNet.

Every model finds dogs much more easily than cats. Dog recall is about 97–98% for all five models, but cat recall ranges from 79% (ResNet-18) to 90% (ViT). The confusion matrices show the mistakes only go one way: no model ever called a dog a cat, while 9–58 cats were called dogs and 42–59 more were called something else. A big part of the reason is ImageNet itself. It has 118 dog classes but only 5 cat classes, so the models spent far more of their training on dog features and have far more "dog" outputs to land on. A blurry, dark, or partly hidden cat only has to look a little like one of 118 breeds to get pulled into the dog group. This is also why precision looks so high (0.95–0.99): "cat" precision is a perfect 1.000 for every model, and "other" answers never count against precision. Recall and accuracy are the more honest numbers for this dataset.

The "other" answers are near misses, not random noise. The most common ones were lynx and Angora (an Angora rabbit — a fluffy white kitten looks like one), followed by wolf/dingo-type classes and household objects such as bucket, bath towel, plastic bag and dishwasher. In those photos the cat is small or half-hidden and the object fills most of the frame, so the model honestly reports the biggest thing it sees. ImageNet labels each image with one main object, and these models carry that habit over.

Some mistakes come from the data, not the model. 779 of the 1,000 images were classified correctly by all five models, and only 17 fooled every one of them. The error gallery shows why most of those 17 are hard: several cats in one photo, a cat being held by people, a black cat in a dark room, a cat behind a cage, or a tiny cat in a low-resolution photo. One "cat" image is actually a grey "PHOTO COMING SOON" placeholder — a labelling error in the original Kaggle data that passed every automatic curation check (it opens fine, is big enough, and is not a duplicate). Only looking at the errors revealed it. A real project would remove it and do a manual review pass, but it is left in here so the reported numbers match what the pipeline actually produced.

Why the models differ — architecture and complexity.

  • ViT-B/16 splits the image into 196 patches of 16×16 pixels and uses self-attention, so every patch can look at every other patch from the very first layer. A CNN only sees a small neighbourhood per layer and builds up a global view slowly. Global context helps exactly in the hard cases above: a cat that fills only part of the frame, or is partly covered, can still be linked to its ears, eyes and tail elsewhere in the image. It is also the largest model (86.6 M parameters) and these weights were pre-trained on ImageNet-21k (about 14 million images) before being fine-tuned on ImageNet-1k, so it has seen far more animals than the CNNs. Transformers have weaker built-in assumptions about images than CNNs, and they need that much data to pay off.

  • ResNet-50 vs. ResNet-18 is the cleanest comparison because both use the same design and the same training recipe; the only real difference is depth (50 vs. 18 layers) and bottleneck blocks. The deeper network gets +2.7 points of accuracy and fewer cat→dog mistakes (29 vs. 47), because it has more capacity to learn fine-grained features such as face shape and fur texture.

  • EfficientNet-B0 beats ResNet-18 with less than half the parameters (5.3 M vs. 11.7 M). Its depth, width and input resolution were balanced together (compound scaling), and its MBConv blocks use cheap depthwise convolutions plus squeeze-and-excitation, which lets the network re-weight channels based on what is in the whole image — a small step toward the global context that ViT has.

  • MobileNetV2 is the smallest (3.5 M) and fastest model. Its inverted-residual blocks are built for phones, trading some capacity for speed. It still matches ResNet-18 on accuracy, but it has the most cat→dog confusions (58), which suggests its smaller feature set does not separate the two animals as clearly.

Input requirements. All five take a 224×224 RGB image, but their preprocessing differs, and Section 6 printed each pipeline. The ResNets resize to 235 before cropping, the mobile models to 256, ViT to 248, and ViT normalizes with mean/std 0.5 instead of the usual ImageNet statistics. Giving each model its own transform is part of why the comparison is fair. Center-cropping also has a cost on this dataset: many photos are wide, and a cat sitting near the edge can be partly cut off before the model ever sees it. ViT is also locked to its 16-pixel patch grid and learned position embeddings, so running it at a different resolution would need those embeddings to be interpolated, while the CNNs would accept other sizes directly.

Cost and suitability. The accuracy-vs-speed plot shows a clear trade-off. ViT is about 7–10× slower per image than MobileNetV2 or EfficientNet-B0 on CPU for about 4–5 extra points of accuracy over MobileNetV2 (3.7 over EfficientNet-B0). ResNet-50 sits in the middle. For offline batch labelling of a photo collection, ViT-B/16 is the best choice. For a phone app or anything real-time, EfficientNet-B0 is the sweet spot: almost ResNet-50 accuracy at ResNet-18 speed and a fifth of ResNet-50's size.

A caveat on the weights: as explained in Section 5, this run used timm's ImageNet-1k weights inside the torchvision architectures, because torchvision's download server was not reachable. Those weights come from different training recipes than torchvision's own (the ResNets in particular use the stronger "ResNet strikes back" recipe). Re-running the notebook with the official weights should give the same overall picture, but the exact numbers, and possibly the order of the close pairs such as ResNet-18 vs. MobileNetV2, may change.

12. Conclusion¶

Five ImageNet-pretrained models from torchvision.models were evaluated, with no fine-tuning, on a curated and balanced set of 1,000 cat and dog photos, loaded through a custom Dataset class and per-model DataLoaders. ViT-B/16 performed best (93.7% accuracy, 0.963 macro F1), thanks to global self-attention, the most parameters, and the largest pre-training dataset, but it was also by far the slowest. ResNet-50 and EfficientNet-B0 followed, and EfficientNet-B0 gave the best balance of accuracy, size and speed. The smaller ResNet-18 and MobileNetV2 trailed by a few points.

The more interesting finding is that every model shared the same weakness: cats were missed far more often than dogs, mostly being pulled toward the 118 dog classes or toward objects in the scene. That bias comes from the ImageNet label set, not from any one architecture, so picking a bigger model reduces the problem but does not remove it. The natural next step would be to fine-tune the final layer of each model on a two-class cat/dog head, which should close most of that gap, and to manually clean the remaining label noise such as the placeholder image found during error analysis.
